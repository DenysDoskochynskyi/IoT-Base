# Лабораторна робота №5  
**Предмет:** Основи проєктування IoT  
**Тема:** Інтеграція клієнтської частини з бекендом IoT-системи  

---

## Мета роботи
- Навчитися інтегрувати клієнтську частину (мобільний або веб-застосунок) з бекендом, створеним у межах ЛР №4.  
- Забезпечити повний цикл обміну даними між IoT-пристроями, сервером і клієнтом.  
- Ознайомитися з принципами візуалізації даних та дистанційного керування IoT-пристроями.  

---

## Важливе нагадування
Ця лабораторна робота **базується на результатах усіх попередніх лабораторних робіт**:
- **ЛР №1** — створення симульованих або реальних IoT-пристроїв;  
- **ЛР №2** — налаштування MQTT-брокера (AWS IoT Core або HiveMQ) та збереження даних;  
- **ЛР №3** — шифрування/дешифрування MQTT-повідомлень;  
- **ЛР №4** — реалізація бекенду з ендпоінтами `GET /records`, `GET /records?date=...`, `POST /notify`.  

У межах ЛР №5 студенти повинні **під’єднати клієнтську частину** (frontend) до бекенду та реалізувати повноцінний інтерфейс керування і моніторингу IoT-системи.

---

## Завдання
1. **Розробити клієнтську частину (Frontend):**  
   Можливі варіанти:
   - **Мобільний застосунок** (наприклад, на Flutter, React Native, Kotlin, Swift);  
   - **Веб-застосунок** (наприклад, на React, Vue, Angular або простий HTML+JS).  

2. **Інтеграція з бекендом (із ЛР №4):**  
   Клієнт повинен реалізовувати такі запити:
   - `GET /records` — відображення повного списку даних від IoT-пристроїв;  
   - `GET /records?date=YYYY-MM-DD` — фільтрація записів за датою;  
   - `POST /notify` — відправлення команд (наприклад, `ON`/`OFF`) до пристроїв через MQTT.  

3. **Відображення даних:**  
   - Вивести список отриманих записів (ID пристрою, час, значення, статус).  
   - Для hardware-варіанту — отримані MQTT-повідомлення від локального брокера (HiveMQ).  

4. **Керування пристроями:**  
   - Реалізувати кнопку або перемикач, який викликає `POST /notify` для керування пристроєм.  
   - Відображати підтвердження виконання команди.  

5. **Шифрування/дешифрування:**  
   - Під час отримання даних з бекенду розшифровувати їх згідно алгоритму з ЛР №3.  
   - Під час надсилання команд — за бажанням, шифрувати повідомлення.  

---

## Очікуваний результат
- Функціональний клієнт (мобільний або веб), що під’єднаний до бекенду.  
- Коректне відображення отриманих даних та фільтрація за датою.  
- Можливість надсилання команд для керування пристроями через MQTT.  
- Дешифрування отриманих повідомлень перед відображенням.

## Формат звіту
У звіті має бути:
1. **Титульна сторінка:** тема, мета, П.І.Б. студента, група, дата.  
2. **Опис структури проєкту:** коротко пояснити компоненти (frontend, backend, broker, database).  
3. **Скріншоти роботи застосунку:**
   - відображення списку даних;
   - фільтрація за датою;
   - відправлення команд MQTT.  
4. **Фрагменти коду, що реалізують інтеграцію:** запити до API, обробка MQTT, розшифрування даних.  
5. **Висновки:** що вдалося реалізувати, які труднощі виникали, можливі покращення.
